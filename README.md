# 정차 중 영단어 학습 (Pleos Red Light Voca)

신호 대기처럼 차가 서 있는 동안에만 영단어를 음성으로 들려주는 Pleos Connect 차량용 학습 앱이다. 차량의 기어·속도 신호로 정차를 판정하고, 출발 전 '학습 시작'을 누르면, 이후 정차가 확정될 때마다 단어 한 턴("영어 → 뜻 → 영어")을 자동으로 재생한다. 차가 움직이면 트랙을 바로 정지한다.

## ① 개발 환경 및 구현 현황

| 항목 | 내용 |
|---|---|
| 플랫폼 | Pleos Connect v2.1 |
| 언어, UI 툴킷 | Kotlin, Jetpack Compose |
| 아키텍처 | 차량 신호, 학습 규칙, 음성 재생, 화면을 계층별로 나누어 구현 |
| MVP 기능 | 차량 신호 연동, 정차 판정, 정차 중에만 재생, 진도 저장, 학습 화면 |
| 테스트 | 속도·기어를 직접 넣어 보는 차량 시뮬레이터를 내장해 에뮬레이터에서 검증 |

## ② 차량 상태 인식 — Pleos Vehicle SDK·AAOS Car API

- **기어**: Pleos Vehicle SDK의 Gear API로 변속을 구독한다.
- **연결 감시**: 3초마다 기어 상태를 조회해 차량 서비스 연결이 끊기면 감지하고, 자동으로 다시 연결한다.
- **속도**: AAOS `CarPropertyManager`의 `PERF_VEHICLE_SPEED` 속성을 구독한다.
- 두 신호를 하나의 차량 상태 흐름(Kotlin Flow)으로 합쳐 정차 판정에 전달한다.

## ③ 정차 판정 및 학습 제어 로직

| 단계 | 조건 | 결과 |
|---|---|---|
| 감지 시작 | D단, 8km/h 이상이 3초 이상 | 다음 정차를 기다림 (학습을 켤 때 이미 서 있으면 첫 정차는 바로 인정) |
| 정차 확정 | D단, 0.5km/h 이하가 3초 지속(학습 ON 중) | 학습 한 턴을 자동 재생 |
| 즉시 정지 | 3km/h 초과, D단 이탈, 차량 신호 오류 중 하나 | 트랙을 정지 |
| 서행 | 0.5~3km/h | 새 재생을 시작하지 않음 |

- 화면의 '학습 시작'을 자동 재생에 대한 사용자의 명시적 동의로 본다(2026-11-14 결정). 학습을 시작하지 않았거나 앱 연결·프로필 변경 때 시스템이 보내는 자동 재생은 재생하지 않는다.
- 스티어링 휠 Play 키와 앱 화면 '듣기'로도 정차 중에 재생할 수 있다(자동 재생이 아직 쓰지 않은 정차일 때).
- 정차당 1턴만 재생하고, 끝까지 들은 턴만 완료로 저장한다. 중단된 턴은 다음 정차에서 처음부터 다시 재생한다.
- 판정 기준값은 한 곳의 설정 값([`LearningConfig`](app/src/main/java/com/stai/pleos_red_light_voca_app/core/common/LearningConfig.kt))으로 모아 두고, 실차 테스트 결과에 따라 조정한다.

## ④ 음성 재생 — Pleos Music/Audio 앱 개발 가이드·Media3

- Media3로 차량 미디어 앱을 구현했다.
- 가이드대로 앱 카테고리(`appCategory="audio"`)와 런처 노출 정보를 선언했다.
- 차량 미디어 화면과 스티어링 휠 미디어 키에서 오는 재생·일시정지·정지·미디어 ID 기반 재생·검색 기반 재생 명령을 처리한다.
- 정차 자동 재생과 미디어 키 재생 모두 하나의 재생 관문인 [`GatedPlayer`](app/src/main/java/com/stai/pleos_red_light_voca_app/presentation/playback/GatedPlayer.kt)를 거쳐, 학습이 켜져 있고 정차가 확정된 상태에서만 소리가 난다. 앱 연결·부팅 때 시스템이 보내는 자동 재생은 막는다.
- 학습 ON 동안 앱이 재생 서비스에 연결해 두어([`LearningServiceConnection`](app/src/main/java/com/stai/pleos_red_light_voca_app/presentation/playback/LearningServiceConnection.kt)), 정차 시 플레이어가 바로 재생할 수 있게 한다.
- **오디오 포커스**: 재생 전 포커스를 요청하고, 내비게이션 안내 중에는 소리를 줄이며, 통화 등으로 포커스를 잃으면 즉시 멈추고 자동으로 다시 틀지 않는다.
- **서비스 수명**: 가이드의 `onCreate` 때 `startService`, `onTaskRemoved` 종료 순서, 세 손가락 제스처(`onStop`) 시 정지를 반영했다.
- 차량 미디어 라이브러리에는 오디오북으로 분류한다.

## ⑤ 학습 콘텐츠 및 진도 관리

- 커리큘럼은 JSON 카탈로그([`content/catalog.json`](app/src/main/assets/content/catalog.json), 일차별 묶음 → 단어 턴)로 관리한다.
- 코드 수정 없이 카탈로그와 음원 파일만 바꿔 콘텐츠를 추가한다(현재는 앱 업데이트로 배포).
- 단어별 영어·한국어 음원을 "영어 → 뜻 → 영어" 순서의 한 턴 오디오로 학습 시작 때 미리 합쳐 두어, 정차 중 지연 없이 재생한다.
- 진도는 Jetpack DataStore에 커리큘럼별로 저장해, 앱을 다시 켜도 이어서 학습한다.
- 현재 샘플 2일차(20단어)를 넣었다. 앞으로 상업 이용이 가능한 음원으로 바꾸고, 난이도별 커리큘럼과 예문 턴을 더해 한 턴을 5~10초 분량으로 맞춘다.

## ⑥ 운전자 중심 화면 설계

- 화면은 출발 전 설정이 주 용도다. 커리큘럼 선택, 진도 확인, 학습 시작을 한 화면에서 한다.
- 출발 전 '학습 시작'을 한 번 누르면 이후 정차·출발에 맞춰 재생과 정지가 자동으로 이뤄져, 운전 중에는 조작을 요구하지 않는다(주행 중 사용자 조작 요청 0회 목표).

## ⑦ 단계별 개발·검증 계획

| 단계 | 내용 |
|---|---|
| 1단계 (완료) | MVP 기능 구현, 단위 테스트, 디버그 차량 시뮬레이터, 학습 화면(이어 하기 카드 + 콘텐츠 목록) |
| 2단계 | Pleos 에뮬레이터와 Virtual Console로 기어·속도 수신, 미디어 키·미디어 화면 명령 전달, 오디오 포커스, 장시간 대기 후 재생, 신호 대기 중 화면 제한 여부를 통합 검증 |
| 3단계 | 상업용 음원 교체, 난이도별 커리큘럼·예문 턴 확대, 2단계 결과를 반영한 화면 개선 |
| 4단계 | 실차 테스트로 정차 판정 기준값을 조정하고, 출발 감지부터 재생 중단까지의 반응시간과 주행 중 재생 차단 여부를 측정 |

## 빌드·실행

샘플 단어 음원(WAV)은 `app/src/main/assets/audio/`에 들어 있다.

```bash
./gradlew assembleDebug
```

```bash
adb install -r -g app/build/outputs/apk/debug/app-debug.apk
```
